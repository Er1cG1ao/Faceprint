# Faceprint 使用教程

[项目主页](../README.zh-CN.md) · [English](TUTORIAL.md) · **简体中文**

本文描述 1.5.0 测试版。已发布 1.2.1 的布局见 [1.2.1 教程](https://github.com/Er1cG1ao/Faceprint/blob/v1.2.1/Docs/TUTORIAL.zh-CN.md)。

## 首次设置

从 [Releases](https://github.com/Er1cG1ao/faceprint/releases) 下载 ZIP，退出旧版，解压并将 Faceprint 放入 Applications。软件需要 Apple Silicon 和 macOS 15+，使用临时签名，尚未经过 Apple 公证。

首次启动会申请摄像头权限，并提示开启辅助功能权限。在 **General → Permissions**（灵动岛部分下面）查看权限状态：摄像头用于本地识别，辅助功能用于读取支持的系统弹窗并输入密码。如果权限被拒绝，使用对应按钮前往系统设置授权，再返回 Faceprint 刷新状态。

点击 **Unlock session** 并完成 macOS 身份验证。在 **Camera** 选择摄像头，在 **Your Face** 点击 **Enroll my face**，按照圆环完成九方向录入，轻缓转头并保持每个方向；每个方向采集两个样本。之后在 **Password** 保存 Mac 登录密码。摄像头预览仅在录脸时显示。

## 第一次填写密码

1. 完成设置：解锁设置、录入人脸，并保存 Mac 登录密码。
2. 在 **General** 保持 **Press Return after filling** 关闭。
3. 在 **General** 开启 **Enable face-assisted filling**。
4. 打开支持的系统密码弹窗，必要时先点 **Use Password…**，让空密码框获得焦点。
5. 看向摄像头。填入后检查请求与密码框，再自行确认或取消。

填写始终使用保存的真实密码。设置中已移除测试字符模式、摄像头预览以及摄像头和灵动岛测试入口。

默认由你手动打开密码输入界面；开启 Scan Touch ID prompts 后，软件会在支持的指纹提示获得焦点时先扫脸，识别通过后才选择明确的 Use Password 按钮。Faceprint 对同一个输入框只尝试一次；失败后可在失败灵动岛仍显示时悬停鼠标重试（需启用该选项），或关闭弹窗稍等后重新打开。

## 设置锁定与日常自动填充

设置在启动时默认锁定。修改任何选项、重新录脸、更新密码、删除数据或调整开机自启前，先点击 **Unlock session** 或锁图标，完成 macOS 验证。即使自动填充已在运行，每次解锁设置仍需验证。

配置完成并启用填写后，点击 **Lock session** 即可锁定修改权限，已启用的自动填充继续运行。关闭设置窗口也会锁定修改权限，菜单栏应用继续运行；5 分钟没有修改设置后也会自动锁定。锁定设置会取消未完成的人脸录入，但不会中断正在进行的识别和填写。

加密数据会话与设置锁独立。已取消 30 分钟闲置失效。应用启动、锁屏、睡眠或切换用户会话后，仍需一次 macOS 用户在场验证来准备受保护的数据。软件会记住填写开关，并在启动时为已启用的自动填充请求验证。之后数据锁定时，下一个支持的弹窗可发起验证，也可解锁设置会话重试；取消验证后会暂停自动重试，直到你主动重试。恢复填写不会解锁设置。

菜单中的 **Settings…** 可以重新打开设置，**Quit Faceprint** 会退出并清除运行中的数据密钥。

开机自启需要先解锁设置，再到 **General** 开启 **Launch at login**。请先将应用放入 Applications；如需批准，点击 **Open Login Items**。关闭开关则取消注册。登录启动同样遵循上述加密数据验证规则。

## 识别与确认选项

在 **General** 中解锁设置即可调整以下选项，不需要关闭自动填充。识别、摄像头和外观选项会在下一次识别生效。

| 设置 | 行为 |
| --- | --- |
| Dynamic Island：Original / Minimal | 在 General 中选择灵动岛外观。 |
| Passive photo checks (Glance Light) | 可选的明显屏幕反光、脸周围设备边框检查，不要求主动眨眼或转头；新安装默认关闭，选项会被记住。 |
| Scan Touch ID prompts | 默认关闭。在支持的指纹提示中扫脸，通过后选择 Use Password，只填写同一请求中验证通过的空密码框。 |
| Press Return after filling | 默认关闭。开启后，只有真实密码填入验证成功，且再次检查目标后才发送回车。 |

关闭自动回车时，请自行检查请求并点击 **Modify Settings** 或 **OK**。开启后，软件可能直接确认当前具有管理员权限的操作。输入长度验证只确认填入情况；密码是否正确由系统判断。

照片检查可能误判真人，也无法可靠防住回放攻击。普通 RGB 人脸识别可能接受照片或录像，关闭检查时尤其如此。

## 从指纹框开始的自动流程

解锁设置，在 **General → Recognition** 开启 **Scan Touch ID prompts**。如果需要最后自动提交，再开启 **Press Return after filling**，随后保持或启用填写，并锁定设置。

| 指纹提示扫描 | 自动回车 | 行为 |
| --- | --- | --- |
| 关闭 | 关闭 | 你打开密码框，软件识别并填入，你提交。 |
| 关闭 | 开启 | 你打开密码框，软件识别、填入并提交。 |
| 开启 | 关闭 | 软件在指纹框先识别，通过后选择 Use Password 并填入，你提交。 |
| 开启 | 开启 | 软件在指纹框先识别，通过后选择 Use Password、填入并提交。 |

扫脸通过前不点击任何按钮。切换步骤使用明确的辅助功能按钮动作，不发送试探性回车。随后必须出现属于原请求的空密码框；如果更换 Apple 签名的承载进程，还必须核对匹配的请求标题（包括系统设置 unlock/modify 的已知文案别名），以及同一 AX 窗口或原指纹阶段消失后匹配的弹窗位置。请求变化、按钮不可用、超时或验证失败都会停止。如果无法确认承载进程切换后仍为原弹窗，或弹窗文字不匹配，请手动打开密码框并选择 Retry current prompt。此版在已有支持范围内识别英文 Touch ID 提示。

支持的可见指纹弹窗即使没有键盘焦点，也可以被发现。扫脸通过后，Faceprint 会在需要时激活该弹窗，再调用已验证的 Use Password 控件。扫描过程中切换应用会取消本次操作；同时出现多个指纹弹窗时不会自动选择。

扫脸通过后会停止摄像头。切换后最多等待 3 秒，对同一个空且已聚焦的密码框约隔 40 毫秒再确认一次，即可输入密码，不再固定等待动画稳定；不会把密码填进 Finder 的用户名框。衔接失败后不会立即自动再扫一次，可选择 **Retry current prompt** 重试。

## 支持的弹窗

- “隐私与安全性”及匹配的系统设置扩展账户密码弹窗（扩展或原生认证代理承载）。
- 英文 SecurityAgent/LocalAuthentication 原生请求者/操作授权，以及安装器管理员验证。
- Finder 英文 “wants to move … to the Trash” 和 “wants to make changes” 授权弹窗（包括撤销操作）。
- 原生“密码”AutoFill 身份验证，包括 Dia 的 AutoFill；目前依赖英文弹窗文字，并检查当前账户。

软件检查受支持的 Apple 进程与弹窗上下文。任意网页密码框、锁屏解锁、通行密钥和 Apple Pay 授权不在支持流程内。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 录脸时摄像头没有画面 | 在 General → Permissions 检查摄像头权限，在 Camera 选择设备；设置页本身没有实时预览。 |
| 录入中断 | 保持稳定光线和适当距离，轻缓转头。超时后重新开始。如遇崩溃，请提供版本与步骤。 |
| 没有触发识别 | 检查填写已启用、人脸和密码已保存、辅助功能已允许，并让支持的空密码框获得焦点；如加密数据需要验证，使用 Resume autofill。 |
| Dia 有效，其他弹窗无效 | 确认是否属于支持范围、是否使用英文文字；反馈时注明弹窗类型并移除私人信息。 |
| 失败后不重试 | 使用 Retry current prompt，或悬停失败灵动岛。 |
| 睡眠后加密数据锁定 | 使用 Resume autofill 或聚焦下一个支持的弹窗进行验证；设置可以保持锁定，填写开关会被记住。 |
| 无法启用开机自启 | 将应用放入 Applications，并检查系统设置中的登录项批准状态。 |
| 密码填入但系统拒绝 | 检查保存的 Mac 登录密码。软件检查填入情况，macOS 检查密码。 |

## 本地数据与隐私

摄像头画面在本机内存中处理。人脸特征和密码分别以 AES-GCM 加密。受用户在场验证保护的 Secure Enclave P-256 密钥通过 ECDH 与 HKDF-SHA256 派生会话密钥。

为兼容旧版本，保存路径沿用原型名称：

```text
~/Library/Application Support/GlanceFill/vault-v1.json
```

偏好设置使用 `io.github.er1cg1ao.faceprint` 域。硬件密钥材料绑定当前设备，复制 vault 不属于支持的数据迁移方式。其他进程获得不透明的密钥表示后可能发起身份验证请求，但派生会话密钥仍需通过硬件强制的用户在场检查。

**Remove saved data…** 会经过确认后移除保存的人脸和密码。若要停止开机自启，请在移除软件前单独关闭该开关。

反馈问题时请提供应用及系统版本、摄像头型号、复现步骤和状态提示，不要附上密码、vault 文件、人脸模板或摄像头录像。

## 1.2.0 的速度与诊断

同样的 ArcFace 模型和相似度阈值，改为连续两张不同画面匹配，不再固定保持 250 毫秒。模型会预热、相机会复用配置；未开启照片检查时跳过未使用的图像质量计算。支持的可见密码框未聚焦时也能触发识别，通过后再请求焦点。

控件支持时整段设置安全输入框的值；否则使用原有键盘投递路径，取消逐字的额外等待。填入后的快速长度确认仍会保留，匹配即继续，不确定时不会自动回车。

如遇停顿，在该轮操作结束、触发下一轮之前，点击设置状态下方的 **Copy diagnostics**，可复制本轮阶段耗时和系统承载进程信息。不包含密码、人脸、弹窗或文件标题。详见 [性能说明](PERFORMANCE.md)。原生授权的覆盖仍依赖辅助功能结构和可识别的英文文案；网页/应用自有账号、Apple Account、钥匙串或磁盘密码并不是已保存的 Mac 登录密码。


1.2.1 对 System Settings → PrivacySecurity.extension 的固定系统代理关系单独处理：必须已经成功选择 Use Password、仍为 Privacy 请求、Apple 签名有效，且扩展内的空安全输入框已经获得焦点，前台也仍符合原请求。此路径不再要求两个 XPC 进程提供相同的窗口对象或位置元数据。


## 1.3.0 设置布局与编辑

顶部 Session 胶囊负责解锁或锁定设置；General 的自动填写、开机启动归在同一组；原 Recognition 标签页已合并到 General。缺失的权限位于 General 顶部；两项通过后权限块隐藏，Camera 页只保留设备选择与刷新。每项功能的说明位于对应设置行内，开关统一在右侧。

解锁后，无论自动填写开关是否开启，都可以改选项、重新录脸或更新密码。录脸会暂时接管摄像头，结束或取消后恢复自动填写，总开关保持原状态。更新密码会先中断当前自动填写；确认删除人脸与密码后才会关闭填写。开启自动回车对下一轮生效；在当前填写完成提交前关闭它，可以阻止尚未发送的自动回车。


## 1.4.0 测试版：Behavior、Animation 与人脸身份

Session 按钮与红绿灯使用同一套标题栏坐标，所有开关采用 Glance 相同的 small 尺寸。缺失权限放在 General 最上面，两项都允许后隐藏。原 Recognition 组改名 Behavior。设置会话仍在闲置 5 分钟后锁定编辑，但自动填写数据不再因闲置 30 分钟失效；锁屏、睡眠、切换用户或退出仍清除数据会话。

Retry on notch hover 控制失败提示仍可见时的悬停重试。Auto retry once after failure 默认关闭：开启后，识别失败会对同一个重新验证过的系统请求自动重试一次，每次都重新扫脸；进入密码阶段后的失败不会自动重复发送密码。关闭重试选项或自动填写、修改保存数据、睡眠或锁屏会取消等待中的重试，菜单手动重试会重置次数。

Animation 提供 Show animation 和 Minimal／Original 两个带示意图的选项；关闭动画不影响识别、填写和自动回车。空闲时点击样式会预览，真正的识别和录脸优先。

Your Face 使用身份卡片，可通过 + 添加名称和新脸，启用／停用身份，Recapture 重录，或确认删除。只匹配启用的身份；每个启用身份都可以授权填写同一份保存的 Mac 密码。旧单脸数据自动读作一个身份，无须重录；旧数据没有质量记录，显示 not recorded。新采样按 Glance 的 Vision 质量分数显示彩色条。身份列表及其名称、模板均保存在原有加密保险库中。


## 1.5.0：录脸命名、摄像头菜单与更新

新增身份不再提前询问名字。完成九方向录入后，灵动岛进入 Name this face；可以修改预填名称，点 Save 后才写入身份列表。Back 返回重录，关闭设置或取消时不会写入新身份。Recapture 保留原身份名称。摄像头选单改为 Glance 的胶囊按钮样式。

About 的 Check for Updates 从 GitHub 查询最新正式 Release；自动检查每天启动时最多一次，不会自动安装。检测到更高版本且有匹配的 arm64 ZIP 与 GitHub SHA-256 后，可以点击 Install and Restart。软件校验下载、压缩包路径、版本／系统／架构和签名，退出后由独立安装器在原 Applications 路径原子替换，保留旧应用恢复副本，不移动人脸、密码或偏好数据。仅支持用户可写的 /Applications 或 ~/Applications；重新启动仍需按正常流程解锁受保护数据。

目前测试包仍是 ad hoc 签名，机器上没有可用的固定签名证书。自动更新不能单独解决权限继承；ad hoc 的代码身份随版本变化，Camera／Accessibility 仍可能需要重新允许。打包已支持固定 Apple 签名身份，签名版会拒绝身份不兼容的更新。首次从 ad hoc 迁移到固定签名时也可能需要重新授权一次。更新器不会修改 TCC 权限库或放宽签名身份检查。


1.5.1 设置页移除重复的 session／识别状态尾注，并加入 Glance 相同的顶部渐进虚化。诊断复制移到菜单栏菜单中的 Copy diagnostics，菜单栏图标悬停仍显示当前状态。About 保留更新状态与许可链接，密码保存失败仍在对应卡片提示。


## 1.5.2：菜单栏显示

菜单栏菜单仅保留 Settings… 和 Quit Faceprint。General 的 Launch at login 下面增加 Show in menu bar，默认开启并记住选择，修改前需解锁 Session。关闭该开关只隐藏图标，自动填写继续运行；从 Applications 或 Spotlight 再次启动正在运行的 Faceprint 即可重新打开设置，最小化的设置窗口也会恢复。设置打开时，还可在应用菜单里用 Settings…（Command-comma）。

菜单中已移除 Copy diagnostics、Retry current prompt、Resume autofill 和 Lock session；前面历史版本章节提到这些菜单项的地方仅描述旧版。现在通过顶部 Session 胶囊解锁／锁定，数据锁定后解锁设置或打开支持的请求验证恢复，失败重试使用悬停、自动重试一次，或关闭后重新打开系统弹窗。
